| workspace 包版本（`Cargo.toml` 的 `[workspace.package].version`） | `0.1.0` |

`package.json#version`）。本次发布按任务要求保留该常量不变，因此 CLI 报告的版本与
workspace 包版本 `0.1.0` 不同；这是已知、有意保留的 TS 兼容差异，不是构建错误。

仓库当前 `git log` 显示尚无任何提交，因此按约束不创建 tag、不 commit、不 push；
本发布只由 `dist/v0.1.0-alpha/` 与 `SHA256SUMS` 标识。

### 6.3 `docs/history/porting/phase-12b-completion.md` §4（剩余风险）

- daemon token 只打印到 stderr，没有轮换/持久化；默认只绑定 loopback，非 loopback
  部署仍需反向代理提供 TLS 与额外认证。
- `--serve` 仍要求会话有可用模型（与非交互模式的既有检查一致），没有模型时会在进入
  daemon 分支前退出 1。
- IDE 连接只在启动时建立一次；编辑器事件没有持续推送，`openDiff` 虽有 broker 与通知
  路由，但没有工具调用点。
- cron 脚本的沙箱策略沿用 `KIANA_SANDBOX_POLICY`；没有独立的 cron 策略配置项。
- web 工具的默认激活依赖注册时的环境变量；在 settings 里配置 key 不会改变默认值。

## 7. 回滚

- 本发布不安装任何系统文件；产物只在 `dist/v0.1.0-alpha/`。回滚即停止使用并删除该目录。
- 没有 git commit/tag 可回退；发布状态由目录名与 `SHA256SUMS` 标识。
- 本步骤没有运行数据迁移，也没有改写 `~/.kiana/agent` 下的配置与会话；回滚二进制不需要
  回滚用户数据。
- daemon 只在显式 `--serve` 时运行；回滚时先向进程发送 SIGINT 停止 daemon，再删除产物。
- 如需重建：按第 2 节命令重新构建，并用第 3 节的 `SHA256SUMS` 比对。
